# Notes

- Packaging uses `uv_build` with `module-name = "opencaselaw"` because the distribution name (`opencaselaw-client`) differs from the import package. Tests deliberately avoid a source-path override so broken installations remain visible.
- The response models cover selected fields and preserve original payloads in `raw`. Unknown fields survive parsing; before the October fixes, HTTP-success error payloads also survived parsing; model construction alone does not establish a successful lookup. The demo's saved `StG`/`ZH` response contains `error` and `candidates` rather than article text.
- This repository is a synchronous client library. Application deployment, database, telemetry, and agent-orchestration guidance in `AGENTS.md` does not imply those systems exist or need to be added here.
- See [README.md](README.md#configuration) for timeout and pacing behavior and [the compatibility reference](docs/api-compatibility.md) for contract evidence and its limits. Earlier timing observations are not maintained benchmarks or service guarantees.
- Live read-only review on 2026-10-13: the deployed application schema still contains all 51 operations in the saved public contract, with no structural parameter changes after excluding descriptive metadata. Its other 11 operations are quota/billing/admin routes outside the documented scope. The research schema and tool catalog are available. POST request fields match the wrappers; POST execution was not tested.
- On that deployment, `get_decision("4A_747/2012", full_text=False)` returns HTTP 404, while `4A_747_2012` and `bger_4A_747_2012` resolve. Percent-encoding the slash preserves the request URL but does not make the deployed route accept it; mock transport path assertions cannot verify routing compatibility.
- The README citation example, `cite("BGE 140 III 86", pinpoint="2.3")`, returns `exists: true` but `pinpoint_valid: false`, `pinpoint_status: "invalid"`, and an unpinpointed citation. The warning and suggested valid pinpoints survive only in `Citation.raw`. A decision existing does not establish that the requested passage exists.
- Live `get_cantonal_law("StG", "ZH", article="12")` returns an HTTP 200 error/candidate payload that becomes a `Law` with no identifier and an empty article list. This documented compatibility behavior can conceal lookup failures from callers using only typed attributes.

- October review fixes: slash references now use exact, unambiguous lookup; JSON application failures raise a payload-retaining exception; citation passage status is typed. Automatic config discovery consumes only the `opencaselaw` section, while explicit paths still accept flat files. Disable discovery with `auto_discover_config=False`.
- Full deployed schemas are now vendored with reproducible stored-file hashes. Local tests validate GET contracts, POST field/type contracts, selected response failures, and lookup boundaries. Live smoke tests are explicit opt-ins and passed after the fixes. CI uses SHA-pinned actions and checks Python 3.13/3.14, package builds, wheel imports, and PR dependency review. The user selected GitHub dependency review instead of adding `pip-audit`; this checks introduced dependency vulnerabilities, not the complete installed environment.
