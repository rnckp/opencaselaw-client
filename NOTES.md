# Notes

- OpenCaseLaw's OpenAPI document describes many public responses with untyped `{}` schemas. The client therefore models stable high-use shapes conservatively and preserves unknown fields in `raw` rather than guessing deep response schemas from live examples.
- The live `/courts` endpoint may return a top-level JSON array, not an object. Keep `list_courts()` tolerant of both shapes and use `list_court_models()` when parsed court items are needed.
- `search_decisions()` local overhead is negligible compared with the public API response time. A compact 5-result live `/decisions` search took ~2.6-3.7s in HTTP request time, while JSON decoding and model conversion were each ~0.0001s.
- A broad live `/decisions` search for `Bundesgericht` with `limit=3` took ~11s on 2026-05-23. Use `search_decisions(..., request_timeout=60.0)` in notebooks or demos where transient API slowness would otherwise trip the 30s default.
- The live `/mock-decision` research helper can exceed the general 30s client timeout. Use `mock_decision(..., request_timeout=120.0)` in examples or interactive notebooks instead of raising the global default for all endpoints.
- Packaging uses `uv_build` with `module-name = "opencaselaw"` because the distribution name (`opencaselaw-client`) differs from the import package. Tests deliberately avoid a source-path override so broken installations remain visible.
- Response and configuration models are now frozen Pydantic models. `from_json()` preserves original payloads in `raw`, including nested records, but known malformed fields raise validation errors instead of being coerced or silently discarded. Dataclass utilities and positional construction are no longer supported; nested collections and `raw` remain mutable.
- This repository is a synchronous client library. Application deployment, database, telemetry, and agent-orchestration guidance does not justify introducing those systems here. The request delay is per instance and intended for sequential use, not thread-safe or shared across clients.
- A user notebook run of `/relevant-erwaegung` hit the default 30s read timeout. The helper now accepts a per-call `request_timeout`; the demo uses 120s. This allows more time but does not guarantee that the upstream service responds.
- The 2026-09-27 deployed API audit is recorded in `docs/api-compatibility.md` with a request-contract fixture. The website can lag deployed routes: use the application schema for methods/parameters and the typed research subset for response semantics. Relevant-Erwägung REST uses `top_k` (not `max_paragraphs`); decision search rejects `decision_type`. Law article text and the articles collection can be absent/null under the typed contract.
